# 09 · 商业化与广告系统设计

> 《Bug哥：别相信你的第一眼》商业化方案：以激励视频（IAA）为主、去广告会员与皮肤（IAP）为辅。
> 本文档是广告模块、会员模块、皮肤模块的唯一业务依据，与 `07-数据模型设计.md`、`12-抖音平台集成与传播设计.md` 配合使用。

## 1. 商业模式总览

### 1.1 定位与原则

- **核心变现：IAA（In-App Advertising）**，激励视频（Rewarded Video）为绝对主力，设 4 个点位。
- **辅助变现：IAP（In-App Purchase）**，去广告会员（订阅制）+ 皮肤（一次性买断），通过抖音虚拟支付（预留，见 `gd_payment`）结算。
- **设计铁律**：广告只出现在玩家"想要更多"的节点，绝不断崖式强制插入，保护《Bug哥》的剧情沉浸感与解谜爽感。

### 1.2 收入结构占比（目标）

| 收入来源 | 目标占比 | 说明 |
| --- | --- | --- |
| 激励视频广告 | 65% ~ 75% | 4 点位 + 每日挑战复活，渗透率目标 ≥ 60% |
| 去广告会员 | 15% ~ 20% | 高频玩家转化，订阅式 |
| 皮肤买断 | 5% ~ 10% | 一次性收入 + IP 情感溢价 |
| 其他（联名/彩蛋） | 0% ~ 5% | 二期起，随 IP 成熟逐步引入 |

### 1.3 付费转化路径

```
免费玩家 ──高频卡关──> 看提示广告 / 复活广告 ──> 形成"看广告=变强"心智
     │                                          │
     └────────── 广告频次高、留存好 ──────────────┘
                          │
                    去广告会员（直接获得提示/复活/双倍权益）
                          │
                    皮肤买断（为 IP 情感付费）
```

## 2. 激励视频 4 点位详细设计

> 点位枚举与 `gd_ad_reward.ad_type`（hint / revive / double / clue）严格一致。

### 2.1 点位总览

| 点位 | ad_type | 触发场景 | 奖励内容 | 单日频控 | 单关频控 |
| --- | --- | --- | --- | --- | --- |
| 提示 | hint | 关卡内点击"求 Bug 哥帮帮忙" | 按提示档位逐级解锁：1 级文字提示 → 2 级圈出关键区域 → 3 级直接给答案步骤 | 8 次/日 | 3 次/关（同一关只能升档，不可重复看同一档） |
| 失败复活 | revive | 卡关超时/尝试失败后的"再给一次机会" | 当前关重开一次，保留已解锁提示档位；每关限 1 次 | 5 次/日 | 1 次/关 |
| 双倍奖励 | double | 通关结算页（Aha 动画后） | 本关星星翻倍，额外 +1 金币/积分；分享图解锁"双倍"徽章 | 3 次/日 | 1 次/关 |
| 隐藏线索 | clue | 隐藏关入口 / 彩蛋关内 | 解锁 1 条隐藏 Bug 线索（Bug 日志隐藏条目），指向彩蛋 | 3 次/日 | 1 次/隐藏关 |

### 2.2 点位触发时机（与游戏流程对齐）

```
进入关卡 ──> 卡壳（超平均时间 1.5 倍）──> 出现提示按钮（hint）
   │
   ├── 尝试失败 N 次 / 超时 ──> 失败弹窗（revive）
   │
   通关 ──> 结算页（Aha 动画后）──> 双倍入口（double）
   │
   收集满隐藏线索 ──> 解锁隐藏关（clue 在隐藏关内触发）
```

| 时机 | 设计要点 |
| --- | --- |
| 首次触发 | 第 1 关不出现任何广告入口，让玩家先完整体验解谜乐趣（保护首关完成率）；第 3 关起开放 hint。 |
| 主动引导 | 卡壳超过该关平均通关时间 1.5 倍时，提示按钮做呼吸光效 + Bug 哥口播"我有一招，想不想听？" |
| 结算页 | double 按钮默认高亮，但文案克制："要不要翻个倍？"；不弹窗强制。 |
| 隐藏关 | clue 只在隐藏关内出现，且与 Bug 日志收藏（`gd_bug_log`）联动，制造"集齐彩蛋"目标。 |

### 2.3 频控与限流（服务端强制，客户端展示）

| 维度 | 规则 | 实现 |
| --- | --- | --- |
| 单日总次数 | 每日每人 ≤ 12 次（4 点位合计），防止广告疲劳 | Redis `gd:rate:{userId}:ad_daily`，TTL 至次日 0 点 |
| 点位级频控 | hint 8 / revive 5 / double 3 / clue 3 | 上表，Redis 计数器 |
| 关卡级频控 | 每关 hint ≤ 3 次、revive ≤ 1 次、double ≤ 1 次 | 客户端本地计数 + 服务端 `gd_ad_reward` 按 (user_id, level_id, ad_type) 计数校验 |
| 连续观看 | 两次广告间隔 ≥ 90 秒（客户端软限制 + 服务端校验时间戳） | 防"连刷刷量" |
| 新用户保护 | 注册 24 小时内 hint 点位每日 ≤ 3 次 | 保护新手体验，防过早广告疲劳 |

### 2.4 防滥用与反作弊

| 风险 | 手段 |
| --- | --- |
| 伪造"看完广告"回调 | 服务端调抖音 `/api/apps/v2/verify_order`（或等价服务端验证接口）校验回调 ID 真实性，校验通过才发放奖励（详见第 3 章） |
| 重复领取 | `gd_ad_reward.platform_order_id` 唯一键幂等，同一回调 ID 只能发放一次 |
| 多开/批量刷量 | 频控 + 单日上限 + 同 openid 单设备绑定（`gd_user` 记录 last_login 设备指纹，异常弹窗人工复核） |
| 时间作弊 | 服务端校验广告完成时间与请求发放时间的间隔（≥ 广告最短时长 10s）；低于阈值判定为伪造 |
| 客户端劫持 | 奖励发放只认服务端 `ad/verify` 结果，客户端任何"直接发奖励"的代码路径必须经过验证接口 |

## 3. 广告服务端验证流程

### 3.1 时序图

```
客户端                       后端(NestJS)                    抖音服务端
  │  ① 触发点位，请求开始广告       │                              │
  │ ────────────────────────> │                              │
  │                            │  ② 返回本次广告凭证(ad_token)   │
  │ <────────────────────────  │                              │
  │  ③ tt.createRewardedVideoAd 播放                        │
  │  onClose({isEnded:true})    │                              │
  │  ④ 上报 ad_watch 事件 + 回调ID│                              │
  │ ────────────────────────>  │  ⑤ 服务端调抖音验证接口         │
  │                            │ ──────────────────────────>  │
  │                            │  ⑥ 返回验证结果(合法/伪造)      │
  │                            │ <──────────────────────────  │
  │                            │  ⑦ 校验通过 → 写 gd_ad_reward │
  │                            │     发放奖励 → 记 ad_verify    │
  │  ⑧ 返回发放结果            │                              │
  │ <────────────────────────  │                              │
```

### 3.2 后端接口约束

| 接口 | 说明 |
| --- | --- |
| `POST /ad/start` | 领取一次"广告会话"，服务端登记 `ad_type`、`scene`、`level_id`，返回 `ad_token`（防止客户端自造请求） |
| `POST /ad/verify` | 客户端在广告 `onClose(isEnded=true)` 后调用，携带 `ad_token` + 抖音回调数据；服务端验证通过才写 `gd_ad_reward`（verify_status=2）并发放奖励 |
| 失败路径 | 验证拒绝（verify_status=3）→ 不发放奖励，返回明确错误码，客户端展示"广告异常，请稍后再试"，**不展示错误细节**（防注入信息泄露） |

### 3.3 幂等与审计

- 唯一键：`gd_ad_reward.platform_order_id`（抖音回调 ID），重复请求直接返回已发放结果（幂等）。
- 审计：`gd_ad_reward` 保留 verify_status 状态流转（1 待验 → 2 通过 / 3 拒绝），运营可追溯每一笔奖励。
- 对账：每日定时任务统计"广告回调数 vs 发放数"，偏差超阈值（如 > 1%）告警。

## 4. 去广告会员

> 会员表：`gd_member`（member_type = `vip_member`）；订单预留：`gd_payment`。

### 4.1 权益清单

| 权益 | 免费玩家 | 会员玩家 | 说明 |
| --- | --- | --- | --- |
| 激励视频点位 | 全部可用（受限流） | **全部免广告直接获得** | 核心权益：提示/复活/双倍/隐藏线索一键解锁 |
| 广告展示 | 全部展示 | 不展示任何激励视频 | 会员期间广告点位全部静默，不出现广告按钮 |
| 皮肤 | 需单独购买 | 会员专属 1 款（"金色 Bug 哥"）+ 其余皮肤 9 折 | 会员皮肤为 `gd_skin` 中 unlock_type=member 的条目 |
| 每日挑战 | 1 次免费复活 | 每日挑战复活不限次 | 提高会员每日活跃价值 |
| Bug 日志 | 正常收藏 | 隐藏线索自动解锁（无需看广告） | 降低收集门槛 |
| 特殊标识 | 无 | 头像框 + 结算页金色徽章 | 社交货币，配合分享图展示 |

### 4.2 定价建议（估算，以 2026 年抖音小游戏常规区间为参考）

| 档位 | 定价 | 定位 | 备注 |
| --- | --- | --- | --- |
| 周卡 | ¥6（首周特惠 ¥3） | 新手尝鲜 | 拉新转化，降低决策成本 |
| 月卡 | ¥12 | 主力档 | 对标休闲解谜游戏 10~15 元月卡区间 |
| 季卡 | ¥25 | 中高频玩家 | 相当于月卡 8.3 折 |
| 终身卡 | ¥30（限量活动价 ¥18） | 深度玩家 | 提高 LTV 天花板，但需谨慎设置，避免冲击订阅收入 |

> 定价仅为建议区间，需结合抖音虚拟支付费率与竞品定价在二期实测调整。

### 4.3 到期处理

| 场景 | 行为 |
| --- | --- |
| 到期前 3 天 | 结算页 + 每日挑战页显示"会员即将到期"轻提示（非弹窗），附续费入口 |
| 到期当天 | 弹窗告知"会员已到期，广告恢复"，给 1 次 3 天体验续费券（每用户限 1 次） |
| 到期后 | 广告点位恢复；已解锁的会员专属皮肤**保留但不可穿戴**（穿戴态回退默认皮肤），Bug 日志已解锁内容保留 |
| 退款/异常 | 走 `gd_payment` 状态机，退款后同步回收会员权益；杜绝"退款白嫖"（幂等 + 对账） |

## 5. 皮肤商业化

> 皮肤表：`gd_skin`（skin_key 枚举：programmer / detective / chef / ancient）；玩家拥有：`gd_user_skin`。

### 5.1 四款皮肤定价与解锁方式

> 下表与 `init-schema.sql` 种子数据、`gd_skin.unlock_type` 枚举（ad/iap/event/member）严格一致；`price` 单位为分。

| skin_key | 名称 | 解锁方式 | 定价（分） | 设计要点 |
| --- | --- | --- | --- | --- |
| programmer | 程序员 Bug 哥 | 初始赠送（event） | 0 | 默认赠送！新手进入即解锁，用于教学"皮肤系统"存在 |
| detective | 侦探 Bug 哥 | 看广告解锁（ad） | 1500 | 单次激励视频看完即解锁；风衣 + 放大镜，推理向玩家首选 |
| chef | 厨师 Bug 哥 | 看广告进度解锁（ad） | 1500 | 广告进度制：累计看完 3 次解锁，免费玩家专属获取路径，展示"广告换皮肤"心智 |
| ancient | 古代 Bug 哥 | 买断（IAP） | 2000 | 高溢价款，联动限时活动（如春节档）制造稀缺 |

### 5.2 解锁规则细节

- programmer 为默认皮肤（`unlock_type=event`、price=0），`gd_user_skin` 中 source=`default`，玩家可穿戴/更换，不产生收入但保留"拥有感"。
- detective 走单次广告解锁：`ad/verify` 校验通过后自动写入 `gd_user_skin`（source=`ad`），同一皮肤不可重复解锁（`UNIQUE(user_id, skin_id)` 幂等）。
- chef 走广告进度制：`gd_ad_reward.ad_type=hint` 中携带 skin_progress 属性；累计看完 3 次即自动写入 `gd_user_skin`（source=`ad`），中断不重置。
- ancient 买断支付成功后由 `gd_payment` 回调驱动写入 `gd_user_skin`，服务端为唯一写入方。
- 会员专属皮肤（unlock_type=member，如"金色 Bug 哥"）为二期预留条目，一期种子数据不含。
- 同一皮肤不可重复购买（`UNIQUE(user_id, skin_id)` 幂等）。
- 皮肤仅影响 Bug 哥形象与结算动画，不影响关卡判定（严禁"付费变强"，保护公平性）。

### 5.3 皮肤与传播联动

- 通关分享图（见 12 文档）右下角展示玩家当前穿戴皮肤，形成"炫耀 → 他人想拥有 → 转化"闭环。
- 结算页展示皮肤使用时长（"穿着侦探皮肤通关了 37 关"），强化 IP 情感绑定。

## 6. 收益模型预估

> 以下全部为**估算值**，用于排期与验证假设，非承诺收益。需在二期用真实数据回填校准。

### 6.1 假设输入

| 参数 | 取值 | 说明 |
| --- | --- | --- |
| eCPM（激励视频，元/千次） | 20 ~ 60 | 按抖音激励视频 2025~2026 年区间假设，取中值 40 |
| 激励视频单价 | 0.02 ~ 0.06 元/次 | = eCPM / 1000 |
| 日活跃玩家（DAU） | 10 万（上线 3 个月假设） | 依赖短视频投放量 |
| 人均广告次数（人均广告/日） | 4 ~ 6 次 | 目标渗透率 60% × 人均 7~10 次点位触达 |
| 广告渗透率 | 60% | 看过至少 1 次广告的 DAU 占比 |
| 会员月卡转化率 | 1.5% DAU | 月度口径 |
| 皮肤付费率 | 0.5% DAU | 月度口径 |

### 6.2 ARPU 计算示例表（估算）

| 场景 | eCPM 低（20） | eCPM 中（40） | eCPM 高（60） |
| --- | --- | --- | --- |
| 人均广告/日 = 4 | 广告 ARPU = 4 × 0.02 = **0.08 元** | 4 × 0.04 = **0.16 元** | 4 × 0.06 = **0.24 元** |
| 人均广告/日 = 6 | 6 × 0.02 = **0.12 元** | 6 × 0.04 = **0.24 元** | 6 × 0.06 = **0.36 元** |

> 说明：广告 ARPU（元/DAU/日）= 人均广告次数 × 激励视频单价。IAA 侧收入随 eCPM 与人均广告次数线性变化。

### 6.3 收入测算表（DAU = 10 万，估算）

| 收入项 | 计算式 | 中值场景（eCPM=40，人均广告 5） |
| --- | --- | --- |
| 广告日收入 | DAU × 人均广告 × 单价 | 100,000 × 5 × 0.04 = **20,000 元/日** |
| 广告月收入 | 日收入 × 30 | **600,000 元/月** |
| 会员月收入 | DAU × 月卡转化率 × 月卡价 | 100,000 × 1.5% × 12 = **18,000 元/月** |
| 皮肤月收入 | DAU × 皮肤付费率 × 均价 | 100,000 × 0.5% × 12（均价） = **6,000 元/月** |
| **月度总收入（估算）** | 广告 + 会员 + 皮肤 | **约 62.4 万元/月** |
| **ARPDAU（估算）** | 月收入 / DAU / 30 | 约 **0.21 元** |

### 6.4 敏感性结论（估算）

- eCPM 从 20 涨到 60，广告月收入在 30~90 万区间波动，**eCPM 是最大杠杆**，需持续优化广告填充率与点位曝光质量。
- 人均广告次数从 4 提到 6（提升点位触达效率），广告收入 +50%，但受频控上限 12 次/日约束，不可无限拔高。
- 会员+皮肤合计约占总收入 4%：当前阶段以广告为主；会员、皮肤价值在于长期 LTV 与 IP 情感，而非短期大盘。

### 6.5 关键监控指标（收益侧）

| 指标 | 定义 | 预警阈值 |
| --- | --- | --- |
| 广告渗透率 | 当日看过广告用户 / DAU | < 40% 预警 |
| 人均广告 | 当日广告总次数 / DAU | < 3 次预警（点位曝光不足） |
| 广告完成率 | 完整看完广告次数 / 广告播放次数 | < 70% 预警（点位时机差） |
| 会员渗透率 | 有效会员 / DAU | 上线 30 天 < 1% 预警 |
| 皮肤付费率 | 当月购买皮肤用户 / DAU | < 0.3% 预警 |

## 7. 合规要点

### 7.1 抖音广告规范

- 所有广告播放走 `tt.createRewardedVideoAd`，展示样式、关闭按钮位置遵循抖音官方模板，禁止遮挡/诱导关闭（"点击即看"类诱导被判定违规）。
- 激励视频奖励描述必须与发放一致：广告按钮上明确写"看广告得 1 级提示"，**禁止夸大或虚假奖励文案**。
- 广告必须在用户主动点击后播放，禁止静默预加载并自动弹出；播放中不得叠加其他交互层。
- 广告内容出现违规素材（如涉赌、医疗夸大）时，需在服务端下架对应广告位并上报抖音平台。
- 每点位广告位 ID 在抖音开发者后台单独创建并区分用途，便于数据归因。

### 7.2 未成年人保护

- 依据《未成年人保护法》与抖音平台未成年人保护规范：
  - 广告频控对未成年账号进一步收紧（hint 每日 ≤ 2 次、revive ≤ 1 次），实现方式：`gd_user` 增加 `is_minor` 标记（由抖音侧年龄能力或用户自填，见 12 文档登录章节）。
  - 会员与皮肤付费对未成年账号**默认关闭 IAP 入口**，展示"未成年人请勿购买"。
  - 不设任何诱导未成年人消费的机制（不搞"抽奖保底"式诱导）。

### 7.3 隐私与数据

- 埋点上报（见 10 文档）遵循最小化原则：不采集通讯录、位置、相册等敏感信息；仅采集玩法行为数据。
- 用户身份仅使用抖音 openid（服务端加密存储），不保存明文手机号。
- 隐私政策需在首启弹窗中展示并取得同意；用户可随时在设置页关闭广告个性化（个性化广告关闭后仍可观看非个性化广告，频控不变）。
- 广告 ID（ad_unit_id）属于平台配置，不进客户端源码硬编码的敏感清单；token、密钥仅存后端环境变量。

### 7.4 支付合规（IAP 侧，二期）

- 虚拟支付必须走抖音官方支付通道，禁止私域收款。
- 订单与权益发放以 `gd_payment` 状态机为准，服务端校验回调签名，杜绝伪造支付成功。
- 保留 7 天无理由退款能力（抖音虚拟支付规则），退款后回收权益并记录审计。
