## 1. Cocos Creator 3.x 工程结构（assets 目录规划）

工程位于 `project/frontend/`，H5 预览/部署端口 **1024**。

```
project/frontend/
├── assets/
│   ├── scenes/                     # Cocos 场景文件（场景与状态机见第 3 章）
│   │   ├── Boot.scene              # 启动：初始化 + 资源预检
│   │   ├── Login.scene             # 登录（平台授权）
│   │   ├── MainMenu.scene          # 主菜单
│   │   ├── LevelSelect.scene       # 选关
│   │   ├── Level.scene             # 关卡运行时（解释器动态填充，通用单场景）
│   │   ├── Result.scene            # 结算
│   │   ├── Settings.scene          # 设置
│   │   ├── BugLog.scene            # Bug 日志收藏
│   │   ├── Shop.scene              # 商城（会员/皮肤，IAP 预留）
│   │   └── Skin.scene              # 皮肤
│   ├── scripts/
│   │   ├── core/                   # EventBus、ServiceLocator、工具（第 6 章）
│   │   ├── ui/                     # UI 层：界面控制器（MainMenuUI、LevelSelectUI…）
│   │   ├── gameplay/               # 玩法层：GameFlow 状态机、LevelRuntime、HintService
│   │   ├── interpreter/            # 关卡解释器：LevelParser/SceneBuilder/Binder/Judge
│   │   ├── platform/               # 平台适配层：接口 + douyin/wechat/h5 实现
│   │   ├── data/                   # 数据层：PlayerDataService、LevelRepo、ServerApi
│   │   └── config/                 # 常量与枚举（GameState、GameEvents、AdPlacement…）
│   ├── resources/
│   │   ├── prefabs/                # 通用 UI 预制体（按钮/弹窗/Toast/星级面板）
│   │   ├── textures/               # 图集与贴图（按 UI/关卡物件/特效分包图集）
│   │   ├── audio/                  # 音效（sfx_*）与 BGM（bgm_*）
│   │   ├── data/
│   │   │   ├── levels/             # 关卡 JSON 包（levels_001.json…，bundle: levels）
│   │   │   ├── dialogue/           # 台词表 dialogue_zh.json（Bug 哥台词库）
│   │   │   └── config/             # 游戏数值配置（难度/成长/广告点位）
│   │   └── skins/                  # 皮肤资源（bundle: skins）
│   ├── bundles/                    # 分包声明（main/levels/skins/audio）
│   └── settings/                   # Cocos 项目设置（Bundle 配置、Layers）
├── package.json
└── tsconfig.json
```

### Bundle 划分

| Bundle | 内容 | 加载时机 |
| --- | --- | --- |
| main | 场景、UI 预制体、核心脚本、台词表 | 启动即加载 |
| levels | 关卡 JSON 包（内置 + 热更） | 按需加载 |
| skins | 皮肤资源 | 选关后/商城打开时 |
| audio | 音效与 BGM | 首次进入关卡时预载 |

## 2. 分层架构

```
┌─────────────────────────────────────────────────────────────┐
│  UI 层（Cocos 场景 + Prefab + 界面控制器）                    │
│  渲染交互、弹窗、Toast、星级面板，不写业务规则                  │
└───────────────────────────┬─────────────────────────────────┘
                            │ 事件驱动（GameEvents）
┌───────────────────────────▼─────────────────────────────────┐
│  玩法层（GameFlow 状态机 + LevelRuntime + HintService）       │
│  游戏规则、关卡生命周期、星级计算、广告点位调度                  │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  关卡解释器（LevelParser → SceneBuilder → Binder → Judge）    │
│  纯逻辑：JSON → LevelModel → 场景构建 → 交互绑定 → 胜负判定    │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  数据层（PlayerDataService / LevelRepo / ServerApi）          │
│  本地存档、关卡包缓存、HTTP 上报                               │
└───────────────────────────┬─────────────────────────────────┘
                            │
┌───────────────────────────▼─────────────────────────────────┐
│  平台适配层（PlatformAdapter / AdService / ShareService…）    │
│  抖音 / 微信 / H5 实现，业务代码只依赖接口                      │
└─────────────────────────────────────────────────────────────┘
```

### 依赖规则

1. 上层依赖下层接口；禁止反向依赖（UI 层禁止 import 平台实现）。
2. 关卡解释器为**纯逻辑**：不 import 任何 Cocos 引擎类型（模型层与渲染层隔离），保证可单元测试。
3. 玩法层只依赖解释器暴露的 LevelModel 与事件，不感知具体关卡内容。
4. 平台适配层由 `PlatformFactory.create()` 按运行环境实例化，注入到 ServiceLocator。
5. 数据层为唯一允许 import 平台 Storage/HTTP 能力的层。

## 3. 场景与状态机设计

### 3.1 场景划分

| 场景 | 说明 |
| --- | --- |
| Boot | 资源预检、ServiceLocator 注册、读本地存档、跳转 Login 或 MainMenu |
| Login | 平台授权登录（抖音 tt.login），成功后进 MainMenu |
| MainMenu | 主菜单：进入选关、Bug 日志、商城、设置、每日挑战入口 |
| LevelSelect | 章节 + 关卡地图，星级展示、隐藏关入口 |
| Level | 关卡运行时通用场景，由解释器动态构建全部玩法节点 |
| Result | 结算：星级、Bug 日志解锁、剧情、分享、激励视频双倍 |

Settings / BugLog / Shop / Skin 为覆盖在 MainMenu 之上的子场景/弹窗层。

## 4. 关卡解释器设计

### 4.1 执行流程（JSON → 场景构建 → 交互绑定 → 胜负判定）

```
LevelRepo.get(levelId) ──→ 关卡 JSON（本地包或热更缓存）
        │
        ▼
LevelParser.parse(json) ──→ LevelModel（防御性校验 + 模型化）
        │
        ▼
SceneBuilder.build(levelModel) ──→ 场景节点树（背景/物件/文字/粒子）
        │
        ▼
InteractionBinder.bind(levelModel, nodeMap) ──→ 5 种触发器注册
        │
        ▼
Judge 判定（wrong 计数 / right 按 successMode 结算）──→ LevelRuntime
```

### 4.2 模块职责

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| LevelRepo | 按 levelId 取关卡 JSON，管理本地包与热更缓存 | 返回原始 JSON，不解析语义 |
| LevelParser | JSON → LevelModel，防御性校验（必填/引用/枚举） | 纯函数，可单测；不依赖 Cocos |
| LevelModel | 数据模型：ObjectModel / ActionModel / HintModel / BugLogModel | 只读，解释器不修改原始 JSON |
| SceneBuilder | 按 LevelModel 创建节点树、设置 Sprite/Label/粒子、状态机初始态 | 输出 nodeMap（id → 节点） |
| InteractionBinder | 按 ObjectModel.actions 注册 tap/doubleTap/longPress/drag/combine | 绑定失败不吞异常，上报错误 |
| Judge | 判定 wrong/right、维护错误计数、successMode 结算 | 纯逻辑，可单测 |
| LevelRuntime | 协调解释器各模块与玩法层，暴露生命周期（start/win/lose/quit） | 玩法层唯一入口 |
| HintService | 3 档提示发放、冷却、广告消耗调度 | 消费点对接 AdService（docs/09） |

### 4.3 胜负判定逻辑（Judge）

```typescript
type SuccessMode = 'any' | 'sequence' | 'combo';

class Judge {
  private errorCount = 0;
  private seqIndex = 0;          // sequence 模式进度
  private comboStartTime = 0;    // combo 模式时间窗起点

  constructor(private mode: SuccessMode, private rightActions: ActionModel[]) {}

  /** 命中一个动作后的判定；返回 win / fail / continue */
  onAction(action: ActionModel, nowMs: number): JudgeResult {
    if (action.result === 'wrong') {
      this.errorCount++;
      return { type: 'wrong', errorCount: this.errorCount };
    }
    switch (this.mode) {
      case 'any':
        return { type: 'win' };
      case 'sequence':
        if (this.rightActions[this.seqIndex]?.id === action.id) {
          this.seqIndex++;
          if (this.seqIndex >= this.rightActions.length) return { type: 'win' };
          return { type: 'progress', step: this.seqIndex };
        }
        return { type: 'fail', reason: 'sequence_miss' }; // 顺序错误，给出顺序提示
      case 'combo':
        // 时间窗内必须按顺序连续命中
        if (nowMs - this.comboStartTime > COMBO_WINDOW_MS) {
          this.seqIndex = 0;
          this.comboStartTime = nowMs;
        }
        if (this.rightActions[this.seqIndex]?.id === action.id) {
          this.seqIndex++;
          if (this.seqIndex >= this.rightActions.length) return { type: 'win' };
        }
        return { type: 'progress', step: this.seqIndex };
    }
  }
}
```

- wrong 命中：错误计数 +1 → 播放反馈（bugTalk/音效/震动）→ 由 LevelRuntime 通知玩法层。
- right 命中：按 successMode 结算；`onSuccess` 副作用（setState/show/hide/playAnim/unlockBugLog/gotoResult）依次执行。
- condition（state/count/time）在 Binder 注册时求值，不满足则动作不触发。
- 星级在结算时计算：错误 ≤ 2 且未用提示 = ★3；错误 ≤ 4 或用过 1 级提示 = ★2；其余 = ★1（与 docs/03 一致）。

## 5. 平台适配层接口定义

> 业务代码只依赖下列接口。抖音/微信/H5 各提供实现类，由 `PlatformFactory.create()` 按环境选择并注入 ServiceLocator。广告验证由服务端完成（docs/09），客户端只上报完成事件。

### 5.1 平台适配器（PlatformAdapter）

```typescript
/** 平台通用能力：登录、震动、系统信息、本地存储 */
export interface PlatformAdapter {
  readonly platform: 'douyin' | 'wechat' | 'h5';

  /** 平台登录：抖音/微信取 code 换 openid（服务端换取 token），H5 走游客模式 */
  login(): Promise<LoginResult>;

  /** 当前是否已有有效会话 */
  isLoggedIn(): boolean;

  /** 获取服务端 token（登录成功后设置） */
  getToken(): string | null;

  /** 震动反馈（错误反馈/彩蛋触发） */
  vibrate(pattern?: number[]): Promise<void>;

  /** 系统信息（屏幕尺寸、平台版本、网络类型） */
  getSystemInfo(): SystemInfo;

  /** 本地键值存储（存档底层，加密由数据层负责） */
  getStorage(key: string): string | null;
  setStorage(key: string, value: string): void;
  removeStorage(key: string): void;
}

export interface LoginResult {
  code: string;          // 平台授权 code，交后端换取 openid + token
  success: boolean;
  error?: string;
}

export interface SystemInfo {
  screenWidth: number;
  screenHeight: number;
  pixelRatio: number;
  networkType: 'wifi' | '4g' | '5g' | 'none';
  platformVersion: string;
}
```

### 5.4 工厂与实现

```typescript
/** 平台工厂：按运行环境创建适配实现 */
export class PlatformFactory {

    adapter: PlatformAdapter;
    ad: AdService;
```

## 6. 事件总线与依赖注入

### 6.1 事件总线（EventBus）

全局单例，用于 UI ↔ 玩法 ↔ 解释器解耦。事件名集中在 `GameEvents` 常量表。

```typescript
export class EventBus {
  private static _instance: EventBus;
  private map = new Map<string, Set<Function>>();

  static get instance(): EventBus {
    if (!this._instance) this._instance = new EventBus();
    return this._instance;
  }

  on<T>(event: string, handler: (payload: T) => void): void {
    if (!this.map.has(event)) this.map.set(event, new Set());
    this.map.get(event)!.add(handler);
  }

  off<T>(event: string, handler: (payload: T) => void): void {
    this.map.get(event)?.delete(handler);
  }

  emit<T>(event: string, payload?: T): void {
    this.map.get(event)?.forEach((h) => h(payload));
  }

  clear(): void {
    this.map.clear();
  }
}

export const GameEvents = {
  LevelWin: 'level_win',
  LevelWrong: 'level_wrong',
  HintRequested: 'hint_requested',
  HintGranted: 'hint_granted',
  PlayerDataChanged: 'player_data_changed',
  AdRewardGranted: 'ad_reward_granted',
  StateChanged: 'state_changed',
} as const;
```

### 6.2 依赖注入（ServiceLocator）

轻量服务定位器：启动时在 Boot 阶段注册全部服务，运行期只读。

```typescript
export class ServiceLocator {
  private static services = new Map<string, unknown>();

  static register<T>(key: string, service: T): void {
    this.services.set(key, service);
  }

  static resolve<T>(key: string): T {
    const s = this.services.get(key);
    if (!s) throw new Error(`[ServiceLocator] 未注册服务: ${key}`);
    return s as T;
  }

  static clear(): void {
    this.services.clear();
  }
}

export const ServiceKeys = {
  PlatformAdapter: 'platform_adapter',
  AdService: 'ad_service',
  ShareService: 'share_service',
  PlayerData: 'player_data',
  LevelRepo: 'level_repo',
  ServerApi: 'server_api',
} as const;
```

注册时机（Boot）：

```typescript
// Boot 场景入口
const { adapter, ad, share } = PlatformFactory.create();
ServiceLocator.register(ServiceKeys.PlatformAdapter, adapter);
ServiceLocator.register(ServiceKeys.AdService, ad);
ServiceLocator.register(ServiceKeys.ShareService, share);
ServiceLocator.register(ServiceKeys.PlayerData, new PlayerDataService(adapter));
ServiceLocator.register(ServiceKeys.LevelRepo, new LevelRepo());
ServiceLocator.register(ServiceKeys.ServerApi, new ServerApi(adapter));
```

## 7. 资源管理与热更策略

### 7.1 资源管理

| 策略 | 说明 |
| --- | --- |
| 图集 | UI 图集、关卡物件图集、特效图集分离，减少 draw call |
| 预载 | 进入选关场景时预载当前章节图集 + levels bundle 首包 |
| 池化 | 特效/Toast/弹窗使用对象池，避免关卡内频繁创建销毁 |
| 引用管理 | 场景切换时按 bundle 卸载（levels/skins 可整体 release） |

### 7.2 关卡包热更

```
关卡包结构：levels_v{version}.json（清单）+ level_{id}.json（单关）
清单：{ version: "1.0.0", levels: [ {levelId, hash} ... ] }
```

| 环节 | 策略 |
| --- | --- |
| 内置包 | 客户端随包内置 v1 关卡包（1-20 关，保证离线可玩首章） |
| 校验 | 启动/进入选关时请求服务端关卡清单接口（docs/08），比对 version 与 hash |
| 增量拉取 | 只下载新增/变更关卡 JSON，写缓存（平台 Storage），失败重试 3 次 |
| 更新时机 | 选关界面加载时后台拉取，不阻塞首局 |
| 完整性 | 下载后本地 hash 校验，损坏则回退内置包并上报 |
| 灰度 | 服务端按版本/渠道灰度下发，客户端遵循 schemaVersion 兼容策略（docs/04 第 8 章） |

### 7.3 本地存档

- PlayerDataService 封装存档：进度、星级、金币、能力等级、日志收藏、设置、皮肤。
- 写盘节流（2 秒合并写），关键节点（结算）即时写盘。
- 存档数据加密混淆（平台 Storage 层之上），防明文篡改；服务端同步存档兜底。

## 8. 性能目标

| 指标 | 目标 | 说明 |
| --- | --- | --- |
| 冷启动首屏 | < 3 秒（H5）/ < 1.5 秒（抖音原生） | Boot 阶段资源预检并行化 |

| 卡顿监控 | 帧率掉档自动降画质 | 不依赖外部监控，客户端本地降级策略 |
