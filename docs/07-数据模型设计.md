# 07 · 数据模型设计

> 《Bug哥：别相信你的第一眼》数据模型：MySQL 8.0 表结构 + Redis 键设计。
> 本文件是 `docs/database/init-schema.sql` 的唯一依据，两者必须字段级一致。

## 1. 约定

- 库名：`glitch_detective`，字符集 `utf8mb4` / `utf8mb4_unicode_ci`
- 表前缀：`gd_`
- 主键：`BIGINT UNSIGNED AUTO_INCREMENT`
- 通用字段：`created_at`、`updated_at`（`DATETIME`，默认 `CURRENT_TIMESTAMP`）
- 软删除：`is_deleted TINYINT(1) DEFAULT 0`
- 所有金额单位：分（避免浮点误差）
- 所有 ID 对外用字符串（雪花/自增 + 混淆），禁止暴露自增主键

## 4. Redis 键设计

| 键 | 类型 | 说明 | 过期 |
| --- | --- | --- | --- |
| `gd:session:{token}` | STRING | 登录会话（值=userId） | 7d |
| `gd:rank:{type}:{period}` | ZSET | 排行榜（score=得分） | 周期结束+1d |
| `gd:level:{levelId}` | STRING(JSON) | 关卡内容缓存 | 24h |
| `gd:level:list` | STRING(JSON) | 关卡列表缓存 | 1h |
| `gd:daily:{date}` | STRING(JSON) | 每日挑战配置 | 48h |
| `gd:rate:{userId}:{scene}` | STRING(INT) | 限流计数 | 窗口 |
| `gd:ad:verify:{platformOrderId}` | STRING | 广告验证幂等 | 24h |

## 5. 一致性约束

- 外键：业务层保证，DB 层不强制外键（避免性能损耗），但脚本中保留索引
- 幂等：广告奖励、每日奖励、支付回调均按唯一键去重（UNIQUE 或 Redis SETNX）
- 软删除：业务表默认 `is_deleted` 过滤，物理删除仅运维手动
