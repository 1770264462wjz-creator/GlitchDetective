# 00 · 项目概览与目录规范

> 本文件是《Bug哥：别相信你的第一眼》项目的总纲，描述项目背景、目标、范围、术语表与目录规范。其他文档如有冲突，以本文 + README 为准。

## 1. 项目背景

抖音休闲解谜小游戏赛道竞争激烈，但普遍存在以下问题：

| 问题 | 本项目对策 |
| --- | --- |
| 谜题靠脑洞、答案牵强 | 坚持「现实逻辑解谜」，答案必须符合常识可解释 |
| 无角色 IP，换皮成本低 | 打造固定角色「Bug哥」，形成长期 IP 资产 |
| 关卡一次性消耗 | 数据驱动 + 内容管线 + AI 辅助，可持续生产 1000+ 关卡 |
| 变现单一 | 激励视频 + 会员 + 皮肤 + 广告位组合变现 |

## 2. 项目目标

| 目标 | 说明 |
| --- | --- |
| 核心体验 | 玩家获得「原来如此」的恍然大悟感 |
| 留存 | 剧情悬念 + 成长系统 + Bug 日志收藏 + 隐藏关彩蛋 |
| 变现 | IAA（激励视频为主）+ 少量 IAP（去广告会员、皮肤） |
| 扩展 | 架构支持 1000+ 关卡、AI 生成、玩家 UGC、IP 生态 |

## 3. 明确不做（边界）

- 不做科幻/魔法/超自然解谜
- 不做复杂 3D 场景（2D 解谜为主）
- 第一阶段不做 AI 自动生成关卡（第三阶段）
- 第一阶段不做玩家 UGC（第三阶段）
- 不接入真实支付（仅广告变现 + 会员预留）

## 4. 术语表

| 术语 | 定义 |
| --- | --- |
| Bug哥 | 主角 IP，有意识的小 Bug 程序角色，生活在现实世界 |
| 关卡（Level） | 单局解谜内容，数据驱动（JSON） |
| 章节（Chapter） | 关卡分组，按难度/场景主题 |
| 误导层（Mislead） | 玩家第一次按常识得到的错误思路 |
| 真相层（Truth） | 符合现实逻辑的正确解 |
| Aha Moment | 恍然大悟时刻，核心爽感 |
| 卡关 | 玩家在关卡停留过久（超过阈值） |
| 提示（Hint） | 分档提示，1/2/3 级 |
| 激励视频（RV） | Rewarded Video，看广告换奖励 |
| Bug 日志 | 每关解锁的「错误记录」收藏品 |
| 观察/调查/提示能力 | 成长系统三类能力 |
| 难度星级 | 1~5 星 |
| 卡点分析 | 按关卡维度的流失/卡关数据 |

## 6. 目录规范

```
GlitchDetective/
├── README.md                  # 总览（端口、连接信息、索引）
├── docs/                      # 全部设计文档
│   └── database/              # 建库脚本
├── prototype/                 # 高保真 HTML 原型
├── project/
│   ├── frontend/              # Cocos 游戏源码（1024）
│   ├── editor/                # 关卡编辑器 Vue3 源码（1025）
│   └── backend/               # NestJS 后端源码（2010）
├── database/                  # 脚本副本（与 docs/database 同步）
└── utils/                     # 关卡校验器等工具包
```

### 目录使用规则

1. 文档统一放 `docs/`，命名 `NN-主题.md`（NN 为序号）
2. 新建文件前必须校验目录结构，缺失即补齐
3. 原型放 `prototype/`，高保真可交互，确认后才进入开发
4. 游戏前端代码只放 `project/frontend/`，关卡编辑器代码放 `project/editor/`，后端只放 `project/backend/`
5. 数据库脚本主副本在 `docs/database/`，发布前同步到 `database/`
6. 端口分配唯一，修改需先在全局扫描查重
