## 4. 鉴权设计

### 4.1 登录流程（抖音）

```
客户端启动 → 平台适配层调 tt.login() 拿临时 code
→ POST /api/v1/auth/login {code, nickname, avatar_url}
→ 后端用 DOUYIN_APPID + DOUYIN_SECRET 调抖音开放平台 code2Session 接口换 openid
→ 按 openid 查 gd_user：不存在则创建（注册即登录，platform=douyin）
→ 签发 JWT（payload: userId / platform / tokenVersion，有效期 7d）
→ 写入 Redis gd:session:{token} = userId（TTL 7d，双通道校验）
→ 返回 {token, expires_in, user}
```

- 密钥仅服务端持有，客户端只传临时 code；openid 属敏感字段，日志脱敏、接口不返回。
- 后续请求通过 `Authorization: Bearer <token>` 携带凭证。

### 4.2 token 签发

- 算法 HS256，密钥来自环境变量 `JWT_SECRET`；payload 不含昵称头像等可变信息，仅含 `userId`、`platform`、`tokenVersion`。
- **双通道校验**：JWT 验签（防篡改）+ Redis 会话存在性（可主动失效）。封禁/踢下线只需删除 `gd:session:{token}`，JWT 立即失效，无需等自然过期。
- token 刷新策略：登录返回 7 天 token；临近过期（剩余 <1d）由客户端静默重新登录换取，一期不单独提供 refresh token 接口。

### 4.3 中间件与守卫

| 组件 | 类型 | 职责 |
| --- | --- | --- |
| LoggerMiddleware | 中间件 | 全量请求日志：requestId、method、path、状态码、耗时、userId（脱敏） |
| GlobalValidationPipe | 管道 | 所有 DTO 校验，失败返回 1001 |
| AllExceptionsFilter | 过滤器 | 兜底：业务异常/系统异常统一转为 `{code,message,data}` |
| TransformInterceptor | 拦截器 | 成功响应统一包装 `{code:0, message:'ok', data}` |
| JwtAuthGuard | 守卫（全局） | 除 `@Public()` 外的全部接口校验 token |
| ThrottleGuard | 守卫 | 按 `userId+场景` Redis 计数限流（登录/广告/埋点/提交） |

守卫核心逻辑（伪代码）：

```typescript
async canActivate(context: ExecutionContext): Promise<boolean> {
  const req = context.switchToHttp().getRequest();
  if (this.reflector.isPublic(context.getHandler(), context.getClass())) {
    return true;                                   // @Public() 放行（如 /auth/login）
  }
  const token = this.extractBearer(req.headers.authorization);
  if (!token) throw new BusinessException(ErrorCode.TOKEN_MISSING);   // 2001
  const payload = this.jwtService.verify(token);   // 验签，失败抛 2003
  const userId = await this.redis.get(`gd:session:${token}`);
  if (!userId) throw new BusinessException(ErrorCode.TOKEN_EXPIRED);  // 2002
  req.user = { userId, platform: payload.platform };
  return true;
}
```

## 5. 广告验证流程（防伪造核心链路）

### 5.1 时序（文字描述）

```
① 玩家点击激励视频点位 → 客户端先 POST /api/v1/ad/start 登记会话（ad_type/scene/level_id）
   ├─ 服务端前置校验：登录态、点位合法性、频控（gd:rate:{userId}:{scene}）、会员无需看广告直接发
   └─ 校验通过返回一次性凭证 ad_token（防自造请求）
② 客户端携带 ad_token 调抖音广告 SDK（rewardedVideoAd）播放
③ 播放完成 → 抖音 SDK 在客户端返回本地凭证（ad_unit_id、orderId/transId 等）
   ※ 客户端侧凭证一律视为不可信
④ 客户端 POST /api/v1/ad/verify 上报：{ad_token, ad_type, scene, level_id, platform_order_id, ad_unit_id}
⑤ 后端校验 ad_token 有效性（未开启会话的请求直接拒绝 4021）
⑥ 后端携带广告位 ID + 凭证调抖音服务端广告验证接口（服务端到服务端）
   ├─ 验证通过：走发奖事务 → 写 gd_ad_reward(verify_status=2) → 更新进度/能力 → 返回成功
   └─ 验证失败（凭证无效/已消费）：写 gd_ad_reward(verify_status=3) → 返回 4021
⑦ 若该 platform_order_id 已存在处理记录 → 直接返回既有结果（幂等，不重复发奖）
```

### 5.2 幂等防重（三层）

1. **数据库唯一键**：`gd_ad_reward` 的 `UK(platform_order_id)`。重复插入触发 DuplicateEntry 时捕获并回读旧记录返回，天然去重。
2. **Redis 锁**：`SETNX gd:ad:verify:{platformOrderId}`（TTL 24h）。抢锁失败说明该凭证正在处理或已处理，直接返回处理中/已处理结果，防止并发双发。
3. **事务内发奖**：开事务 → 锁用户进度行（`SELECT ... FOR UPDATE` by user_id）→ 写入 gd_ad_reward → 更新 gd_user_progress / gd_user_skill → commit；任一步失败整体回滚，不出现"记录已写、奖励未发"的中间态。

### 5.3 核心伪代码（ad.service.ts）

```typescript
async verifyAndReward(dto: AdVerifyDto, userId: string) {
  const orderId = normalizeOrderId(dto.platformOrderId);

  // ① 幂等查询：已处理直接返回
  const exist = await this.adRepo.findOne({ where: { platformOrderId: orderId } });
  if (exist) return this.toResult(exist);

  // ② Redis 分布式锁防并发双发
  const locked = await this.redis.setnx(`gd:ad:verify:${orderId}`, '1', 86400);
  if (!locked) throw new BusinessException(ErrorCode.AD_REWARD_PROCESSING); // 4092

  try {
    // ③ 前置校验：会员免广告 / 频控 / 点位合法
    if (await this.memberService.isMember(userId)) {
      return this.grantRewardDirect(userId, dto);      // 会员直接发奖，不调抖音
    }
    await this.checkQuota(userId, dto.scene);

    // ④ 调抖音服务端验证（服务端到服务端，防伪造）
    const ok = await this.douyinApi.verifyRewardedAd(dto.adUnitId, orderId);
    if (!ok) {
      await this.adRepo.save({ ...dto, userId, verifyStatus: 3 }); // 记审计
      throw new BusinessException(ErrorCode.AD_VERIFY_FAILED);      // 4021
    }

    // ⑤ 事务发奖（唯一键兜底幂等）
    await this.dataSource.transaction(async (m) => {
      const reward = this.buildReward(dto.adType, dto.scene);       // 见 09 奖励表
      await m.save(GdAdReward, { ...dto, userId, verifyStatus: 2, reward: JSON.stringify(reward) });
      await this.applyReward(m, userId, reward, dto.levelId);       // 更新进度/能力/收藏
    });
    return { rewarded: true, reward };
  } finally {
    await this.redis.del(`gd:ad:verify:${orderId}`);
  }
}
```

客户端在发奖响应丢失/超时（网络异常）时，可用 `POST /ad/reward-claim` 按 `platform_order_id` 补偿领取：服务端只查询已通过（verify_status=2）的记录补发一次，未验证通过的记录不补发，杜绝"未看广告领奖"。

## 6. 排行榜实现（Redis ZSet + 定期落库）

| 榜类型 type | 键 | score 语义 | 周期 period |
| --- | --- | --- | --- |
| daily 日榜 | `gd:rank:daily:{date}` | 当日得分（同分先完成者优先，见编码） | `2026-08-07` |
| weekly 周榜 | `gd:rank:weekly:{week}` | 周得分 | `2026W32` |
| level 关卡最快 | `gd:rank:level:{levelNo}` | 最快用时（越小越优，用负数编码） | 关卡序号 |

- **写入**：每日挑战结算 / 关卡通关时 `ZADD key score member(userId)`；同分按完成时间靠前者靠前，通过 score 编码实现：`score = points * 1e7 - (periodStartTs 内的完成毫秒数)`，展示时整除还原分数；关卡榜用 `score = -timeMs`，取 `ZREVRANGE` 即最快。
- **查询**：`ZREVRANGE key 0 99 WITHSCORES` 取前 100，批量回查 gd_user 补昵称头像；本人名次用 `ZREVRANK key userId`。
- **定期落库**：`RankSyncTask` 每小时 + 每日凌晨把各榜单前 N 名快照 upsert 进 `gd_rank`（`UNIQUE(rank_type, period, user_id)` 去重），供运营查询与历史留存；一期不开放历史榜查询接口。
- **过期**：键 TTL = 周期结束 + 1d（与 07 Redis 键设计一致），由 Redis 自动回收，无需清理任务。

## 7. 每日挑战调度（定时任务）

- **生成**：`@nestjs/schedule` 的 Cron 每天北京时间 00:05 执行：从已发布（status=3）关卡中按难度/章节挑选当日关卡（默认 3 关），写 `gd_daily_challenge`（challenge_date=当天、level_ids、reward JSON），并缓存 `gd:daily:{date}`（TTL 48h）。
- **读取**：客户端 `GET /daily` 优先读缓存，未命中回源 DB 再回填缓存。
- **提交**：`POST /daily/submit` 校验：challenge 存在且 status=1（生效）→ 按 `UNIQUE(user_id, challenge_id)` 幂等（重复提交返回 4042）→ 计算得分 → 写 `gd_user_daily` → 成绩写入日榜 ZSet → 发放 reward 并标记 reward_claimed=1。
- **兜底**：定时任务失败（DB/Redis 异常）时记录告警日志；次日 00:05 重试生成，当天未生成则 `GET /daily` 返回 4041，不阻塞普通关卡玩法。

## 8. 埋点接收与缓冲

- **入口**：`POST /api/v1/events` 批量上报（单次 ≤ 50 条），客户端埋点定义见 10。
- **处理链**：解析 → 服务端补齐 user_id / platform / app_version / 服务端时间 → 写入**有界内存队列**（容量 10000 条）→ 消费者按「每 200 条 或 5s」批量 INSERT 到 `gd_event`。
- **降级策略**：队列满时丢弃新事件并计数告警（埋点绝不允许阻塞游戏主链路）；单条落库失败不阻塞批次，只记错误计数。
- **生产演进**：后续接入抖音开放平台数据回传/大数据平台，`gd_event` 作为开发期兜底明细（与 07 一致）。

## 9. 错误码体系（4 位码）

统一 4 位数字错误码，`code=0` 表示成功。业务侧一律以 `code` 为准，HTTP 状态码仅表达语义大类。

| 错误码 | 含义 | HTTP | 说明 |
| --- | --- | --- | --- |
| 0000 | 成功 | 200 | 默认 `message: 'ok'` |
| 1001 | 参数校验失败 | 400 | 字段缺失/格式错误/越界 |
| 1002 | 请求体解析失败 | 400 | JSON 非法 |
| 1003 | 资源不存在 | 404 | 关卡/皮肤/挑战不存在 |
| 1004 | 客户端版本过低 | 426 | 需更新小游戏 |
| 2001 | 未登录 | 401 | token 缺失 |
| 2002 | token 过期 | 401 | 会话失效/自然过期 |
| 2003 | token 无效 | 401 | 验签失败 |
| 2004 | 账号被封禁 | 403 | status=2 |
| 3001 | 服务器内部错误 | 500 | 未预期异常 |
| 3002 | 数据访问异常 | 500 | DB 错误 |
| 3003 | 缓存服务异常 | 503 | Redis 不可用 |
| 3004 | 第三方服务异常 | 502 | 抖音接口失败 |
| 4001 | 请求过于频繁 | 429 | 限流触发 |
| 4011 | 回调签名校验失败 | 403 | 服务端回调验签失败 |
| 4021 | 广告凭证无效 | 403 | 抖音服务端验证拒绝（防伪造） |
| 4022 | 广告奖励已发放 | 409 | 幂等重复领取 |
| 4023 | 广告奖励冷却中 | 429 | 同场景频控未到冷却 |
| 4031 | 关卡未解锁 | 403 | 越级请求关卡内容 |
| 4032 | 关卡数据异常 | 500 | 关卡 JSON 校验失败/内容缺失 |
| 4041 | 每日挑战不存在或已结束 | 404 | 未生成/已过期 |
| 4042 | 每日挑战重复提交 | 409 | UNIQUE 冲突 |
| 4051 | 皮肤不存在 | 404 | 未上架/不存在 |
| 4052 | 皮肤未解锁 | 403 | 未拥有该皮肤 |

## 10. 配置管理（环境变量）

- 采用 `@nestjs/config`，本地读 `.env`，生产由部署平台注入；`.env` 不入库、不提交。

## 11. 日志与监控

- **结构化日志**：NestJS Logger + pino，JSON 行格式，`requestId` 贯穿一次请求全链路（中间件生成 → 透传 → 异常过滤器落日志）。
- **请求日志**：LoggerMiddleware 记录 method / path / status / 耗时 / userId；敏感字段脱敏（openid 只保留前 6 位、token 一律不落日志）。
- **分级**：debug / info / warn / error；业务异常（4xxx）记 warn，系统异常（3xxx）记 error 并附带堆栈。
- **错误追踪**：接 Sentry（dev 可关闭），上报 3001/3002/3004 等系统级异常。
- **运行指标**：进程内存、事件循环延迟、接口错误率与 P99 耗时（内存计数，周期输出）；`gd_event` 关注批量写入慢查询（MySQL slow log 阈值 500ms）。

### 12.3 典型 Service（level.service.ts 片段）

```typescript
@Injectable()
export class LevelService {
  constructor(
    @InjectRepository(GdLevel) private readonly levelRepo: Repository<GdLevel>,
    private readonly redis: RedisService,
  ) {}

  async detail(levelId: string, userId: string): Promise<LevelDetailVo> {
    await this.progressGuard(userId, levelId);           // 未解锁抛 4031
    const cached = await this.redis.get(`gd:level:${levelId}`);
    if (cached) return JSON.parse(cached);               // 缓存命中（TTL 24h）
    const level = await this.levelRepo.findOne({
      where: { id: BigInt(levelId), status: 3 },         // 仅发布态可下发
    });
    if (!level) throw new BusinessException(ErrorCode.RESOURCE_NOT_FOUND); // 1003
    const vo = this.toVo(level);                         // 内容经 Schema 校验器过检（见 04）
    await this.redis.set(`gd:level:${levelId}`, JSON.stringify(vo), 86400);
    return vo;
  }
}
```
