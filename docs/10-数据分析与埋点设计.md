# 10 · 数据分析与埋点设计

> 《Bug哥：别相信你的第一眼》数据指标体系、事件字典、漏斗与卡关分析规则、上报协议与看板建议。
> 埋点落库表：`gd_event`（见 07）；本文件为 `gd_event.event_name` 与 `properties` 的唯一枚举来源。

## 1. 指标体系

### 1.1 用户指标

| 指标 | 定义 | 计算方式 | 目标参考 |
| --- | --- | --- | --- |
| 新增用户 | 当日首次进入游戏的用户 | 按 openid 首次出现日去重 | 随投放量波动 |
| 首关完成率 | 完成第 1 关的用户 / 当日新增用户 | level_finish(level_no=1) / app_launch 去重 | ≥ 80%（第 1 关无广告，必保） |
| 次日留存 | 次日再次启动的用户 / 当日新增用户 | D+1 启动 / D 日新增 | ≥ 35% |
| 7 日留存 | 第 7 天再次启动的用户 / 当日新增用户 | D+7 启动 / D 日新增 | ≥ 15% |
| 长期留存（30 日） | 第 30 天再次启动的用户 / 当日新增用户 | D+30 启动 / D 日新增 | ≥ 8%（二期观察） |
| 流失定义 | 连续 7 天未启动 | 最后活跃时间距当日 ≥ 7 天 | 触发流失召回（分享回流） |

### 1.2 关卡指标

| 指标 | 定义 | 说明 |
| --- | --- | --- |
| 关卡平均通关时间 | 该关 level_finish 的 duration_ms 平均值 | 卡关判定基线（见第 4 章） |
| 通关率 | 该关 level_finish 去重用户 / 进入该关去重用户 | 分难度 1~5 星观察 |
| 卡关率 | 卡关用户数 / 进入该关用户数 | 卡关定义见第 4 章 |
| 提示使用率 | 该关 hint_use 次数 / 进入该关用户数 | 反映关卡难度与点位价值 |
| 放弃率 | 该关进入后未完成即退出（无 fail 无 finish）的比例 | 高放弃率 = 体验断裂 |
| 尝试次数分布 | 失败次数分布（1 次/2 次/3 次+） | 超过 3 次未过 → 重点优化 |

### 1.3 变现指标

| 指标 | 定义 | 预警阈值 |
| --- | --- | --- |
| 广告渗透率 | 当日看过广告用户 / DAU | < 40% 预警 |
| 人均广告 | 当日广告总次数 / DAU | < 3 次预警 |
| 点位完成率 | 某点位完整看完 / 该点位播放 | < 70% 预警 |
| 广告 ARPU | 广告收入 / DAU（估算口径） | 见 09 文档 6.5 |
| ARPDAU | 日总收入 / DAU | 见 09 文档 6.3 |
| 会员渗透率 | 有效会员 / DAU | 上线 30 天 < 1% 预警 |
| 付费率 | 付费用户 / DAU | 含会员与皮肤 |

## 2. 事件字典

> 命名规范：英文 snake_case；`properties` 列出关键 key（均为 kebab-free 的 snake_case）；触发时机描述精确到交互节点。
> 公共属性（每个事件必带）：`user_id`、`platform`（douyin/weixin/h5）、`app_version`、`ts`、`session_id`、`level_no`（关卡事件必带）。

### 2.1 生命周期与启动

| # | 事件名 | 关键属性 | 触发时机 |
| --- | --- | --- | --- |
| 1 | app_launch | launch_from（icon/douyin_card/scan/share） | 游戏启动完成（登录成功后） |

## 3. 漏斗分析

### 3.1 首关漏斗（新用户）

```
新增（app_launch 去重）── 100%
   │
privacy_agree ── 期望 99%
   │
onboarding_finish ── 期望 95%
   │
level_start(1) ── 期望 90%
   │
level_finish(1) ── 期望 ≥ 80%（首关完成率核心指标）
   │
level_start(2) ── 期望 ≥ 70%（验证"第二关接住"）
```

| 观察点 | 行动 |
| --- | --- |
| privacy_agree < 98% | 隐私弹窗文案/时机优化 |
| onboarding_finish 断崖 | 新手引导过长，压缩步骤 |
| level_start(1)→finish < 80% | 第 1 关太难或提示缺失，回炉 GDD 难度曲线 |

### 3.2 广告漏斗（以 hint 点位为例）

```
关卡卡壳（超平均时间 1.5 倍，服务端判定）
   │
ad_entry_show（提示按钮亮起）── 期望 ≥ 70% 的卡壳用户看到
   │
ad_click ── 期望 40%（看得到 → 愿意点的转化）
   │
ad_watch(is_ended=true) ── 期望 85% 完整看完
   │
ad_verify(pass) ── 期望 99% 通过
   │
hint_unlock → level_finish ── 期望看广告后通关率 ≥ 70%
```

| 环节 | 低于阈值时 |
| --- | --- |
| 卡壳 → ad_entry_show | 提示按钮曝光时机太晚/样式不醒目，提前到 1.2 倍 |
| show → click | 文案缺乏吸引力，参考"我有一招，想不想听？"口播引导 |
| click → watch | 广告加载慢，预加载优化；或点位入口被误点 |
| watch → verify | 排查抖音广告回调与后端验证链路 |

## 4. 卡关分析规则

### 4.1 卡关定义（阈值）

> 基准定义：**玩家在该关的停留时长 ≥ 该关平均通关时间的 2 倍**，且未完成通关，即判定为"卡关"。

| 规则 | 阈值 | 说明 |
| --- | --- | --- |
| 单次卡关 | 单次 level_start → 退出/失败 的时长 ≥ 该关平均通关时间 × 2 | 平均通关时间取近 7 天滚动均值 |
| 累计卡关 | 同一用户同一关累计尝试次数 ≥ 5 次仍未通关 | 与时长规则取"或"关系 |
| 全局卡关点 | 该关卡关率 ≥ 15% 或 该关放弃率 ≥ 10% | 判定为"内容缺陷关"，进优化队列 |

### 4.2 卡关热力输出

```
按关卡维度输出：
level_no | 平均通关时间 | 卡关率 | 放弃率 | 提示使用率 | 卡关用户数
37       | 95s         | 22%   | 12%   | 58%        | 2,310
```

- 卡关率异常的关（≥ 15%）进入"关卡健康度看板"，由内容管线（11 文档）评估：降低误导层强度 / 调整提示档位 / 直接改关。
- 卡关与提示使用率呈正相关时（卡关 22% + 提示率 58%），优先策略是**优化提示价值**而非削难度。
- 卡关位置分布（按章节聚合）用于内容排期：连续多关高卡关 → 章节难度曲线陡升，需平滑。

## 5. 埋点上报协议

### 5.1 上报链路

```
客户端事件 → 本地批量队列（最多 50 条/批）→ POST /api/v1/events
→ 后端落库 gd_event → （二期）同步数据平台
```

| 项 | 约定 |
| --- | --- |
| 接口 | `POST /api/v1/events`（见 08 文档 3.13），Body 为事件数组，单批 ≤ 50 条，超 50 自动分片 |
| 认证 | 登录态 token；未登录只允许匿名白名单事件（app_launch / login_fail / privacy_agree 等，user_id 为空） |
| 协议 | JSON over HTTPS；请求头带 `app_version`、`platform`、`session_id` |
| 幂等 | 每条事件带 `event_id`（客户端 UUID），服务端按 (user_id, event_id) 去重 |

### 5.2 离线缓存与重试

| 场景 | 策略 |
| --- | --- |
| 网络失败/服务端 5xx | 事件留在本地队列，指数退避重试（1s → 2s → 4s → 最大 60s），最多重试 5 次 |
| 缓存容量 | 本地队列上限 2000 条（约 1MB）；超限丢弃最旧事件并打 `event_drop` 本地日志 |
| 断网时长 > 24h | 队列满时优先丢弃低价值事件（顺序：皮肤展示 > 关卡事件 > 广告事件 > 生命周期事件） |
| 客户端崩溃 | 事件先写本地存储（如 `localStorage`/文件），崩溃恢复后下次启动续传 |

### 5.3 可靠性要求

- 广告类事件（ad_watch / ad_verify / ad_reward_grant）**必达**：不参与批量降级，走单独直传路径（后端代报兜底）。
- 关键业务事件（level_finish、share_success）重试优先级高于普通事件。
- 上报成功率监控：每日 `成功条数 / 应报条数` < 95% 时告警（排查接口或网络）。

## 6. 看板建议

### 6.1 GMV / 变现看板（运营每日）

| 区域 | 指标 |
| --- | --- |
| 今日总览 | DAU、新增、广告收入（估算）、会员收入、皮肤收入、ARPDAU |
| 广告模块 | 渗透率、人均广告、点位分布（hint/revive/double/clue 各自播放与完成）、eCPM（来自抖音后台回填） |
| IAP 模块 | 会员新增/到期、月卡转化率、皮肤销量 TOP、付费率 |
| 趋势 | 近 7 天 / 30 天环比，节假日异动标注 |

### 6.2 关卡健康度看板（内容团队）

| 区域 | 指标 |
| --- | --- |
| 关卡总览 | 每关通关率、平均通关时间、卡关率、放弃率、提示使用率 |
| 异常标记 | 卡关率 ≥ 15% 或 放弃率 ≥ 10% 的关卡自动置顶 |
| 难度分布 | 1~5 星关卡的通关率箱线图，校验难度标注与真实难度是否一致 |
| 趋势 | 关卡包更新前后对比（新关卡是否接住玩家） |

### 6.3 留存与传播看板（增长团队）

| 区域 | 指标 |
| --- | --- |
| 留存曲线 | 次日/7 日/30 日留存，分渠道、分版本 |
| 分享漏斗 | share_click → share_success → open_from_share → 新增 |
| 回流 | open_from_share 的 source_level 分布（玩家从哪关分享、分享带回来多少人） |
| 卡关传播联动 | 第 37 关卡关率 → "99% 卡在第 37 关"短视频素材命中率 |

### 6.4 看板工具选型（开发期兜底）

- 一期：后端定时任务聚合 gd_event 生成 CSV / 简单图表页（NestJS 只读接口 + 看板静态页）。
- 二期：接入抖音开放平台数据回传 / 自建简易数仓（MySQL 汇总表 + 定时聚合），避免直接查询明细表拖慢业务库。
