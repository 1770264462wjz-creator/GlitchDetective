# 02 · 技术选型说明

> 《Bug哥：别相信你的第一眼》各技术层选型理由与对比。所有选型以支撑「现实逻辑解谜 + 固定角色 IP + 抖音广告变现」为目标，核心诉求：一次开发多端、数据驱动 1000+ 关卡、内容生产可持续。
> 本文引用基准：00 项目概览、01 总体架构。如有冲突以 README + 00 为准。

## 1. 选型总览

| 层 | 选型 | 版本建议 | 一句话理由 | 备选方案 |
| --- | --- | --- | --- | --- |
| 游戏客户端 | Cocos Creator + TypeScript | 3.8.x | 抖音官方支持、一次开发多端（抖音/微信/H5）、2D 解谜能力完整 | LayaAir 3.x（已评估否决，见 2.2） |
| 关卡编辑器 | Vue 3 + Vite + TypeScript | Vue 3.4+ / Vite 5.x | 轻量 SPA，JSON 编辑 + iframe 预览，团队熟悉度最高 | React + Vite（能力等价，无迁移收益） |

## 2. 客户端引擎选型对比

### 2.1 对比维度与评分（5 分制，权重已按本项目诉求加权）

| 维度 | 权重 | Cocos Creator 3.8.x | LayaAir 3.x | 原生 H5（自研渲染） |
| --- | --- | --- | --- | --- |
| 抖音小游戏适配 | 30% | 5（官方工具链一键发布，SDK 集成成熟） | 3（支持但社区案例少） | 2（需自研适配层与包体控制） |
| 2D 解谜玩法能力 | 20% | 5（场景编辑器、动画、事件系统开箱即用） | 4（能力有但生态偏 3D 渲染） | 2（全部自研，成本高） |
| 生态与社区 | 15% | 5（国内体量最大，教程/插件/商店丰富） | 3（社区与维护热度较弱） | 3（取决于自研框架选型） |
| 学习成本 | 10% | 4（文档中文完善，TS 友好） | 3 | 3（工程量大，需全栈能力） |
| 包体与性能 | 15% | 4（按需加载、合图优化成熟） | 4 | 3（无框架优化，风险高） |
| 长期维护（多端扩展） | 10% | 5（微信/快手/H5 一套代码） | 3 | 2（每端一套适配） |
| **加权总分** | 100% | **4.75** | 3.25 | 2.45 |

### 2.2 结论：Cocos Creator 3.8.x

- 抖音小游戏生态中 Cocos 是**官方深度合作引擎**，构建流程、包体裁剪、广告 SDK 示例均为行业最成熟；
- 本项目为 2D 现实逻辑解谜，无 3D 需求，Cocos 的场景/节点/动画系统直接覆盖「误导层→真相层」的表现诉求；
- TypeScript 强类型与编辑器联动，符合客户端分层（UI/玩法/关卡解释器/平台适配层）的落地需要；
- LayaAir 在 3D 渲染侧更强，本项目用不上；原生 H5 自研渲染工程量与长期维护成本不可接受。

## 3. 后端框架选型对比

### 3.1 对比维度（5 分制）

| 维度 | NestJS 10（Node 18+） | Express 4（否决） | Koa 2（否决） |
| --- | --- | --- | --- |
| 架构模式与工程化 | 5（模块/DI/守卫/管道，天然分层） | 2（无约束，大项目易乱） | 3（只有中间件模型） |
| TypeScript 一等支持 | 5（装饰器 + 元编程，类型贯穿全链路） | 2（需自行搭建 TS 工程） | 2（同左） |
| 生态（ORM/校验/文档） | 5（TypeORM/Prisma + class-validator + Swagger 一键） | 4 | 3 |
| 性能（基准吞吐） | 4（模块化分层有少量开销，本业务量级无感） | 5 | 5 |
| 学习成本 | 3（概念较多：DI/守卫/管道） | 5 | 4 |
| 长期维护与团队规范 | 5（结构强制统一，多人协作不易失控） | 2 | 2 |

### 3.2 结论：NestJS 10.x

- 本项目的后端是**内容中台**（关卡、用户、存档、排行、广告、埋点、审核流），模块化与工程规范比极致吞吐更重要；
- 关卡校验、广告回调验签、限流、版本发布等横切逻辑用 NestJS 的 Guard/Interceptor/Pipe 表达最清晰；
- class-validator 与关卡 Schema 校验器可共用一套类型定义，减少 04/11 文档到代码的语义损耗；
- **否决 Express**：无工程约束，16 张业务表 + 内容审核流下代码会随规模迅速腐化；**否决 Koa**：能力介于两者之间，生态与规范不占优，无迁移理由。

## 4. 数据库选型对比

### 4.1 对比维度（5 分制）

| 维度 | MySQL 8.0.x | PostgreSQL 16 |
| --- | --- | --- |
| 生态与运维（云厂商/工具/DBA 资源） | 5（阿里云/腾讯云托管成熟，社区资料海量） | 4 |
| JSON 类型能力 | 4（JSON/JSON 索引够用） | 5（JSONB 更强） |
| 事务与并发 | 4 | 5 |
| 团队熟练度 | 5 | 3 |
| 成本（开发期本机环境） | 5（一键安装、稳定） | 4 |

### 4.2 结论：MySQL 8.0.x

- 本项目 JSON 场景仅为「关卡内容存储 + 存档扩展」，MySQL 8.0 的 JSON 类型完全够用，无需 JSONB 级能力；
- 抖音小游戏后端生态（云托管、监控、备份）对 MySQL 支持最成熟，长期运维成本最低；
- 16 张业务表以关系型查询为主（进度、排行、埋点），MySQL 事务与索引能力充分；
- 库名 `glitch_detective`、账号 `gd_app`，字符集 `utf8mb4 / utf8mb4_unicode_ci`（见 README）。

## 5. 缓存选型：Redis 7

| 用途 | 键设计 | 数据结构 |
| --- | --- | --- |
| 排行榜（二期） | `gd:rank:{type}:{period}` | ZSET（score=得分） |
| 登录会话 | `gd:session:{token}` | STRING，7d 过期 |
| 关卡内容热点 | `gd:level:{levelId}` | STRING(JSON)，24h |
| 每日挑战配置 | `gd:daily:{date}` | STRING(JSON)，48h |
| 广告验证幂等 | `gd:ad:verify:{platformOrderId}` | SETNX，24h |
| 接口限流 | `gd:rate:{userId}:{scene}` | STRING 计数 |

- Redis 7 相比 6.x 提供更好的性能与可观测性；相比 Memcached 具备 ZSET/事务等本排行榜与限流所需能力；
- 全部键设计见 07 数据模型文档，此处不重复。

## 6. 编辑器技术栈：Vue 3 + Vite + TypeScript

- **为什么用 Vue 3**：关卡编辑器是「表单密集型 + 实时预览」SPA，Vue 3 组合式 API + 响应式对 JSON 结构编辑最顺手；团队对 Vue 生态熟悉度最高；
- **为什么用 Vite**：启动即热更新，编辑器内嵌 iframe 预览时迭代体验最佳；
- **与游戏客户端的关系**：编辑器是独立 Web 工具（端口 1025），不承担游戏客户端渲染，仅产出并校验关卡 JSON，通过 iframe 内嵌 Cocos H5 构建做试玩预览；
- 编辑器不负责运行时逻辑，游戏客户端由 Cocos Creator 实现，二者职责严格分离。

## 7. 选型风险与备选方案

| 风险 | 等级 | 应对/备选 |
| --- | --- | --- |
| Cocos Creator 大版本升级破坏项目 | 中 | 锁定 3.8.x 系列，禁跨大版本；升级须全量回归试玩 |
| 抖音小游戏包体超限（首包 4MB） | 中 | 资源分包、远程加载、关卡 JSON 走网络下发 |
| 抖音 SDK/审核政策变化 | 中 | 平台适配层隔离 SDK，策略类逻辑可配置化 |
| 后端单点（单实例 + 单 MySQL） | 低（开发/上线初期） | 上线后接云托管 + 主从；本阶段不做分布式 |
| Redis 数据丢失（无持久化） | 低 | 仅缓存与瞬时数据进 Redis，业务数据全量落 MySQL |
| AI 生成关卡质量不可控（三期） | 中 | 机器校验器强制拦截 + 人工审核前置，不合格不发布 |
| 编辑器预览与实际客户端表现不一致 | 中 | iframe 复用同一份 Cocos 构建产物做预览，杜绝双实现 |

## 8. 版本锁定建议

| 组件 | 锁定版本 | 说明 |
| --- | --- | --- |
| Cocos Creator | **3.8.x**（LTS 序列） | 稳定支持抖音小游戏构建；禁止跨大版本 |
| Node.js | **18+**（建议 18.20 LTS 或 20 LTS） | 后端与编辑器共用；NestJS 10 兼容 |
| TypeScript | 5.x | 客户端/编辑器/后端统一 |
| NestJS | 10.x | 与 Node 18+ 匹配 |
| MySQL | **8.0.x** | 禁止降到 5.7（JSON 索引差异） |
| Redis | 7.x | 禁止降到 6.x |
| Vue | 3.4+ | 编辑器 |
| Vite | 5.x | 编辑器 |
| 包管理器 | pnpm 9.x（或 npm 10） | 全仓统一，锁 lockfile |

**版本变更纪律**：小版本升级走常规回归；大版本升级必须先出方案评审（本阶段默认不做任何大版本升级）。
