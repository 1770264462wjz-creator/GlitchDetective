# 13 · 开发路线图

> 《Bug哥：别相信你的第一眼》三阶段路线：Demo 验证 → 商业化完善 → IP 生态。本文引用全部设计文档（00~12），是项目排期、验收与分工的总纲。
> 原则：每阶段有独立验收标准；阶段二依赖阶段一的数据埋点与内容管线；阶段三依赖阶段二的审核与风控能力。

## 1. 三阶段总览

| 阶段 | 名称 | 核心目标 | 关键内容 | 预估周期 | 前置依赖 |
| --- | --- | --- | --- | --- | --- |
| 一 | Demo 验证 | 玩法成立、可提审上线 | Bug哥角色 + 20~30 精品关卡 + 提示系统 + 广告系统 | 4~6 周 | 无（文档 00~13 已完成） |
| 二 | 商业化完善 | 留存与变现闭环 | 皮肤 + 收藏系统 + 每日挑战 + 排行榜 + 会员 | 3~5 周 | 阶段一埋点数据、广告回调验证、内容管线 |
| 三 | IP 生态 | 内容规模化与 IP 资产化 | AI 自动生成关卡 + 玩家 UGC + IP 生态 | 6~10 周（滚动） | 阶段二校验器成熟、审核人力、风控 |

## 2. 阶段一：Demo（4~6 周）

### 2.1 范围

- Bug哥角色：立绘、基础动画、台词系统（默认 + 关卡覆盖）；
- 20~30 个精品关卡：覆盖 5 种 puzzleType、难度 1~5 星、按章节分组；
- 提示系统：1/2/3 级提示，激励视频解锁提示/复活/双倍奖励；
- 广告系统：抖音激励视频 SDK 接入 + 服务端回调验签 + 奖励发放幂等；
- 基础框架：Cocos 客户端分层（UI/玩法/关卡解释器/平台适配层）、NestJS 后端模块、MySQL/Redis、关卡编辑器 v1、埋点基础事件。

### 2.2 里程碑

| 里程碑 | 内容 | 周期 |
| --- | --- | --- |
| M1 | 项目脚手架：前后端仓库、数据库脚本、CI 骨架、编辑器骨架 | 第 1 周 |
| M2 | 客户端核心：关卡解释器跑通 3 个试做关卡 + Bug哥形象与台词 | 第 1~2 周 |
| M3 | 内容生产：编辑器 v1 可用 + 完成 20~30 关全量内容并过校验器 | 第 3~4 周 |
| M4 | 变现闭环：广告 SDK + 回调验签 + 提示/复活/双倍奖励全链路 | 第 4~5 周 |
| M5 | 内测 + 数据验证 + 抖音提审材料准备 | 第 5~6 周 |

### 2.3 验收标准（可勾选）

- [ ] 20~30 关全部通过校验器（error=0），schema_version 统一 v1
- [ ] 关卡解释器可运行全部 5 种 puzzleType，无硬编码关卡
- [ ] 单关首帧 < 1s、单关内存 < 50MB（01 文档非功能指标）
- [ ] 激励视频：播放→回调→服务端验签→发奖全链路，伪造回调被拒绝且记录 gd_ad_reward
- [ ] 1/2/3 级提示逐级正确，低级提示不泄底
- [ ] Bug哥在错误/通关/卡关场景台词正确触发，人设一致
- [ ] 基础埋点事件完整上报（进入关卡/通关/卡关/广告触发/奖励发放）
- [ ] 抖音小游戏提审通过（或拿到明确打回清单并修复）
- [ ] 编辑器完成 1 个真实新关卡的创建→校验→试玩→提交审核→发布→下发全流程

### 2.4 预估周期与资源

- 周期：**4~6 周**（内容与广告联调为最大不确定项，预留 1 周缓冲）；
- 资源：制作人/主策划 1 + 关卡策划 1 + 客户端 1~2 + 后端 1 + 美术 1 + QA 0.5~1。

## 3. 阶段二：商业化完善（3~5 周）

### 3.1 范围

- 皮肤系统：皮肤定义/拥有/穿戴（gd_skin、gd_user_skin），广告或活动解锁；
- 收藏系统：Bug 日志收藏（gd_bug_log），通关解锁「错误记录」收藏品；
- 每日挑战：服务端每日选关（gd_daily_challenge），奖励发放与去重；
- 排行榜：Redis ZSet 实时榜 + 定期落库（gd_rank），周榜结算；
- 会员/去广告：gd_member 权益（本阶段可先做权益逻辑，支付预留 gd_payment）；
- 成长系统完善：观察/调查/提示三类能力（gd_skill、gd_user_skill）。

### 3.2 里程碑

| 里程碑 | 内容 | 周期 |
| --- | --- | --- |
| M6 | 皮肤系统 + 收藏系统 | 第 1~2 周 |
| M7 | 每日挑战 + 排行榜（含 Redis 落库） | 第 2~3 周 |
| M8 | 会员权益 + 能力成长系统 | 第 3~4 周 |
| M9 | 版本回归 + 埋点漏斗分析 + 商业化数据看板 | 第 4~5 周 |

### 3.3 验收标准（可勾选）

- [ ] 皮肤可解锁/穿戴/更换，服务端与客户端状态一致，无越权穿戴
- [ ] 每日挑战按日期唯一生成，奖励领取幂等（重复领取被拒绝）
- [ ] 排行榜实时性 < 5s（ZSet 口径），周榜结算与快照落库正确
- [ ] 广告解锁皮肤/奖励全链路服务端验签，伪造请求被拒绝
- [ ] 会员去广告权益生效，广告点位按权益隐藏
- [ ] 阶段一埋点漏斗完整可查：进入→通关→卡关→广告→留存
- [ ] 新增功能不回归阶段一 20~30 关全部可通关

### 3.4 前置依赖

- **阶段一数据埋点**：每日挑战选关与排行榜需依赖阶段一积累的关卡难度/卡关数据校准；
- **阶段一广告回调验证**：皮肤与奖励的广告解锁复用同一套验签与幂等基建。

## 4. 阶段三：IP 生态（6~10 周，滚动）

### 4.1 范围

- AI 自动生成关卡：LLM 生成器 + 机器校验 + 语义预审 + 人工审核（见 11 文档第 5 节）；
- 玩家 UGC：开放编辑器（简化版）+ 玩家提交 → 机器校验 → 人工审核 → 发布，加入关卡署名；
- IP 生态：Bug哥立绘/台词/皮肤资产独立管理、衍生内容（表情包、短视频模板）、跨平台（微信/快手/H5）；
- 内容规模目标：总关卡量突破 500，AI 辅助产出占比 ≥ 60%。

### 4.2 里程碑

| 里程碑 | 内容 |
| --- | --- |
| M10 | AI 生成器 v1（2 种 puzzleType 试点）+ 生成后校验管线 |
| M11 | AI 人工审核工作台（批量试玩 + 打回 + 改写） |
| M12 | UGC 编辑器开放 + 提交/审核/署名流程 |
| M13 | IP 资产目录 + 表情包/短视频模板 + 多平台发布 |

### 4.3 验收标准（可勾选）

- [ ] AI 生成关卡机器校验通过率 100%（error=0 才入库）
- [ ] AI 生成关卡人工审核通过率 ≥ 40%（管线健康线）
- [ ] UGC 关卡可完成提交→审核→发布→玩家游玩→举报/下架闭环
- [ ] 违规内容（现实逻辑违背/敏感词/抄袭）在审核前被机器拦截
- [ ] 总关卡量 ≥ 500，卡关率与差评率不劣于人工关卡基线

### 4.4 前置依赖

- **阶段二校验器成熟**：AI/UGC 依赖规则完整、相似度检测（W04）与审核工作台；
- **阶段二风控能力**：UGC 依赖举报、下线、用户处罚能力。

## 5. 每阶段风险与依赖

| 阶段 | 风险 | 等级 | 应对 |
| --- | --- | --- | --- |
| 一 | 20~30 关内容质量与产能不足 | 中 | 编辑器模板 + 示例库先行；关卡策划提前并行产内容 |
| 一 | 广告回调联调与抖音审核周期超预期 | 中 | M4 提前接沙箱联调；提审材料 M3 结束即启动 |
| 二 | 埋点数据不足导致每日挑战难度失衡 | 中 | 用难度星级 + 卡关率双口径校准，缺数据时保守选关 |
| 二 | 排行榜并发写热点 | 低 | Redis ZSet 原子操作 + 定期落库，本阶段规模无忧 |
| 三 | AI 生成质量与同质化 | 高 | 机器校验强制闸门 + 相似度检测 + 人工审核不可省略 |
| 三 | UGC 合规与版权风险 | 高 | 敏感词/相似度机器拦截 + 人工抽检 + 举报下线闭环 |

## 6. 发布计划（抖音提审时间线）

```
阶段一 M3 结束（第 4 周）→ 启动提审材料准备
    ├─ 资质：软著登记（可与开发并行申请）、主体信息、类目资质
    ├─ 材料：版本说明、测试账号（含已解锁关卡）、隐私政策、未成年人保护声明
    ├─ 广告合规：激励视频点位说明、奖励规则公示、防诱导点击文案
    └─ 提审 → 初审 1~3 个工作日 → 打回修改预留 1~2 周 → 上线
上线后节奏：首周观察（崩溃/卡关/广告填充）→ 每周小版本迭代（关卡增量 + 修复）
阶段二/三：跟随功能里程碑发版，大版本提前 1 周提交审核
```

- 关键时间：阶段一第 4 周启动提审材料，第 5~6 周提交，预计上线窗口 = 阶段一结束 + 2~3 周；
- 提审前必须完成：广告回调验证自测、敏感词巡检、现实逻辑人工抽检、崩溃率归零。

## 7. 团队分工建议

| 角色 | 职责 | 阶段一 | 阶段二 | 阶段三 |
| --- | --- | --- | --- | --- |
| 制作人/主策划 | 玩法方向、难度曲线、验收把关 | 1 | 1 | 1 |
| 关卡策划 | 关卡内容生产、AI 生成审核 | 1 | 1~2 | 2~3 |
| 客户端工程师（Cocos） | 解释器、UI、平台适配层 | 1~2 | 1~2 | 1~2 |
| 前端工程师（Vue） | 关卡编辑器、审核工作台 | 1 | 1 | 1~2 |
| 后端工程师（NestJS） | 业务模块、广告验签、内容中台 | 1 | 1~2 | 2 |
| 测试工程师（QA） | 功能/回归/提审包验证 | 0.5~1 | 1 | 1~2 |
| 美术/UI | Bug哥形象、皮肤、UI、资源包 | 1 | 1 | 1~2 |
| 运营 | 抖音投放、广告位、数据看板、社区 | 0.5 | 0.5~1 | 1 |

- 阶段一建议核心团队 4~6 人；阶段三随 AI/UGC 上线扩编内容审核与风控人力；
- 所有阶段遵循：里程碑结束即评审，验收清单未全勾选不进入下一里程碑。
